## 高质量校验动作清单（想不出怎么校验时从这里挑）

1. **对拍**：同一问题在 `wonderful-sql` 的示例库和 `sql-tutorial` 的 75 万行库上各跑一次，结果口径不一致就说明至少有一个错。
2. **查行数**：`COUNT(*)` 表级核对 —— 条件聚合写错时，分组行数/总行数最先暴露。
3. **造反例**：故意插入 NULL、重复行、边界日期（月初/月末/闰年 02-29），看 AI 的 SQL 是否会静默丢数据（尤其是 `WHERE` 里写条件 vs `JOIN ... ON` 里写条件的差异）。
4. **看执行计划**：`EXPLAIN` —— 确认没有全表扫描、确认 JOIN 顺序与预期一致；这也正是面试可讲的内容。
5. **交叉验证**：让 AI 用两种写法（窗口函数 vs 自连接；`CASE WHEN` vs `PIVOT`）实现同一需求，两边结果必须逐行一致。
6. **查文档**：牵涉 NULL 语义、`COUNT(*)` vs `COUNT(col)`、`RANK` vs `DENSE_RANK`、MySQL 与 PostgreSQL 方言差异时，以官方文档为准，不采信 AI 记忆。
7. **口述复述**：合上屏幕，把 SQL 的逻辑用中文讲一遍（面试同款检查）。
